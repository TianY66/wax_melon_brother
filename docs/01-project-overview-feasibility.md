# 冬瓜兄弟：项目简介与可行性分析

> 版本注记：本文保留项目最初 MVP 立项视角。当前可玩版本已进入“第二次迭代：双角色 + 波间商店”，实际范围以 [11-iteration-2.md](./11-iteration-2.md) 与 [02-prd.md](./02-prd.md) 为准。

## 1. 项目简介

### 1.1 项目名称
《冬瓜兄弟》

### 1.2 项目定位
《冬瓜兄弟》是一款单人俯视角肉鸽生存类游戏。玩家将扮演“冬瓜兄弟”防卫队的现役成员，在失控后厨与夜市废墟中生存 10 分钟，通过自动攻击、拾取资源和升级三选一不断变强，最终击败终局 Boss 或撑到倒计时结束。

### 1.3 一句话介绍
在暴走后厨的怪潮中，操控冬瓜兄弟一路走位求生、捡取鲜度能量、构筑厨具武器流派，撑过 10 分钟并迎战后厨总控机。

### 1.4 目标平台
- 首发平台：Windows PC
- 操作方式：键盘 + 鼠标
- 显示模式：横屏 16:9

### 1.5 目标用户
- 喜欢《Vampire Survivors》式生存构筑体验的玩家
- 偏好轻量、爽快、10 分钟一局的休闲动作玩家
- 希望通过项目展示完整游戏系统能力的开发者或团队

### 1.6 设计目标
- 30 秒内让玩家理解基础规则
- 3 分钟内让玩家感受到明显成长
- 10 分钟内完成一局完整体验
- 通过有限内容做出完整的战斗闭环和反馈层次

### 1.7 范围边界
本项目明确控制范围，避免开发失控。

必做内容：
- 单局完整循环
- 自动攻击与升级三选一
- 波次推进与 Boss 终局
- 基础 HUD、暂停、结算

不做内容：
- 联机
- 多地图
- 复杂剧情演出
- 多角色差异化战斗体系
- 大规模局外养成

## 2. 世界观与主题包装

### 2.1 主题设定
故事发生在“南门夜市”的后厨工业区。某次冷链设备故障引发整片后厨系统暴走，切菜机、压力锅、清洁球和搅拌无人机集体失控。玩家所属的“冬瓜兄弟”原本是负责夜市安保的民间防卫队，如今只剩“大哥”仍在前线坚守。

### 2.2 标题解释
“冬瓜兄弟”是组织名，不代表必须做双角色同时操作。MVP 版本只实现 1 名可玩角色，兄弟感通过：

- 标题与世界观体现
- 跟随式辅助武器“小瓜无人机”体现
- 结算和升级文本体现

### 2.3 系统包装映射
| 玩法系统 | 包装名称 |
|---|---|
| 经验值 | 鲜度能量 |
| 被动升级 | 调味强化 |
| 武器 | 厨具模组 |
| 精英怪 | 暴走厨电 |
| Boss | 后厨总控机 |
| 地图 | 夜市后厨 |

## 3. 核心卖点

1. 轻喜剧题材和“后厨灾变”包装，区别于常见废土或吸血鬼题材。
2. 肉鸽生存类最核心的爽点完整保留：走位、清怪、升级、构筑、终局。
3. 设计上极度克制，适合两周内完成可演示版本。
4. 技术架构模块清晰，适合后续扩展新武器、新敌人、新地图。

## 4. 可行性分析

### 4.1 产品可行性
肉鸽生存类游戏具备以下优势：

- 核心循环成熟，用户理解成本低
- 内容可以通过“武器 + 被动 + 敌人 + 波次”快速堆出层次
- 单局时长短，便于反复测试和调优
- 即使资源不豪华，也能靠反馈和数值节奏建立可玩性

《冬瓜兄弟》在玩法上借鉴成熟范式，在表现上使用轻喜剧题材做区分，具备较高落地性。

### 4.2 技术可行性
推荐使用 `Godot 4.3` 实现，理由如下：

- 2D 场景与碰撞系统成熟
- 场景和节点结构适合小团队快速迭代
- GDScript 上手快，适合原型到 MVP 的短周期开发
- Windows 导出链路简单，适合快速打包演示

关键技术点均可在 2 周内完成：
- 角色移动与碰撞
- 自动攻击与目标选择
- 敌人刷怪与时间波次控制
- 升级三选一系统
- 对象池与基础性能优化

### 4.3 美术与音频可行性
本项目适合采用低成本但统一风格的资源策略：

- 角色和敌人使用 Q 版、卡通化 2D 精灵
- 武器与特效采用简化几何和明亮色块
- UI 使用高对比、轻厨房工业风
- 音效优先补足命中、升级、死亡、Boss 预警四类关键反馈

即使没有定制美术团队，也能通过：
- 统一配色
- 统一描边
- 统一命名与文案

让成品具有完整感。

### 4.4 进度可行性
项目以两周为上限，采用“先闭环、再扩展”的推进方式。

| 阶段 | 时间 | 目标 |
|---|---:|---|
| 阶段 1 | 第 1~5 天 | 跑通移动、敌人、武器、经验、升级最小闭环 |
| 阶段 2 | 第 6~10 天 | 增加武器、敌人、波次、被动、掉落和精英 |
| 阶段 3 | 第 11~14 天 | 完成 Boss、UI 补全、调平衡、打包演示 |

该节奏与 `game.md` 的建议完全一致，可执行性高。

### 4.5 人员可行性
最小可行配置：

- 1 名主程序：负责战斗、配置、UI、打包
- 1 名兼任策划：负责数值、故事、内容配置
- 1 名兼职美术/音效：负责基础资源整合

若只有 1 人开发，也可通过缩减资源规模完成：

- 武器先做 4 种
- 敌人先做 4 普通 + 1 精英 + 1 Boss
- 单地图、单角色、单模式

### 4.6 风险与应对
| 风险 | 影响 | 应对策略 |
|---|---|---|
| 武器和升级写死在脚本里 | 后续平衡成本极高 | 从第一周开始使用配置驱动 |
| 敌人数过多导致掉帧 | 中后期体验崩坏 | 控制场上上限、投射物上限、对象池复用 |
| 玩法闭环晚于第 5 天才形成 | 后续只能赶工堆内容 | 第一次迭代必须先做核心闭环 |
| 题材有趣但反馈不足 | 游戏“能玩但不爽” | 预留命中、升级、Boss 预警等反馈开发时间 |
| 美术资源风格不统一 | 成品感弱 | 用统一配色和描边规则收口 |

### 4.7 成本与收益评估
成本主要来自：
- 程序实现与调平衡时间
- 资源整理与 UI 打磨
- 测试迭代

收益主要体现在：
- 快速获得一个完整、可演示、可讲述的独立游戏项目
- 能展示系统设计、模块化架构、数值与节奏控制能力
- 后续可直接扩展成正式 Demo

## 5. 结论
《冬瓜兄弟》是一个高可行性的两周肉鸽生存项目。只要严格遵守以下原则，MVP 版本可稳定落地：

1. 先做完整战斗闭环，再做内容扩展。
2. 只做 1 张地图、1 名角色、1 个主要模式。
3. 把可调内容配置化，不把平衡逻辑写死。
4. 把时间优先留给手感、反馈、结算和收尾。
